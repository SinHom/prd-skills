## 标注约定（PRD 全文用这套标记）

| 标记 | 含义 |
|---|---|
| ⭐ | 一期重点，必须做实 |
| `[基础-CRUD]` | 配套非重点，仅列表 + 详情 + 增删改查 |
| `[基础-CRUD+E]` | 含导出 |
| `[基础-CRUD+R]` | 含提醒（如合同到期） |
| `[PRD 有 / 一期不实现]` | PRD 完整写设计但一期不做，保留口子给二期 |
| `[补全]` | AI 智能补全项（理由见 §5.1） |
| `[假设]` | 待确认内容（详见 §5.2 遗留风险） |

**反例禁止**："对齐基础 CRUD 模板""详见 FR-[N] 模板"——一句话逃避，[基础] 模块也必须展开完整 FR。

## 阶段六自检清单（生成后必跑）

详见 `prd-design` skill 的 `references/quality-gate.md`。六维度：

1. **需求清晰度**——每条需求可被研发直接理解？
2. **可测试性**——BDD 必须完整 + 异常流 + 边界值；不能一句话逃避
3. **约束完整性**——8 维异常场景 + 状态流转有条件 + 非功能有指标
4. **范围界限**——[基础] 不偷懒；[基础-CRUD/+E/+R] 子标签细化
5. **一致性与闭环**（**v1.3 实测教训重点**）：
   - 状态枚举全文唯一（术语表与每个 FR 字面一致）
   - 同义/近义术语要识别并统一
   - 数据生命周期定义唯一（其他位置"对齐主条目"+"详见 §X"）
   - 附录/术语表与功能描述无矛盾
   - [基础] 模块必须完整展开
   - 性能等网络值统一
6. **开放问题与风险**——所有 `[假设]` 列出；待确认项集中；无 TODO/省略

critical/major 必须当场修后再交付。
